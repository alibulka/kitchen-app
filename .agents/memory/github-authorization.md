---
name: Независимая авторизация Git и подключения GitHub
description: Как различать ошибку обычного git push и состояние подключённой интеграции GitHub
---

Авторизацию обычного Git и подключённой интеграции GitHub нужно проверять отдельно. Ошибка авторизации при `git push` сама по себе не означает, что подключение GitHub также требует переподключения.

**Why:** В этом проекте обычная отправка была отклонена из-за недействительной авторизации, хотя подключение GitHub успешно читало тот же репозиторий и имело право записи.

**How to apply:** Перед предложением переподключения проверить реальный доступ используемого подключения. Если отправка выполняется через другой канал, сохранить исходную историю и проверить совпадение Git-объектов; не заменять её новым снимком и не использовать принудительную перезапись ветки.

Для крупных Git-объектов нельзя считать `truncated: false` в ответе `shellExec` внутри CodeExecution гарантией полного вывода.

**Why:** Большой вывод может вернуться неполным без корректного признака усечения, а перенос нескольких крупных объектов за один вызов также упирается в общий бюджет файловых операций.

**How to apply:** Передавать крупные объекты сжатыми или небольшими проверяемыми частями. Перед обновлением удалённой ветки обязательно сверять SHA распакованных объектов, деревьев и исходных коммитов.
